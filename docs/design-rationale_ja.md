# 設計理由

[English](design-rationale.md)

この文書は、現在のリファレンス形式がなぜこの設計になっているのかを説明します。本プロジェクトは実験段階のため、これらの判断は実物試験やレビュー後に変更される可能性があります。

## なぜワッシャーなのか

ステンレスワッシャーは安価で入手しやすく、紙と比べて耐熱性があり、ボルトに通してまとめやすい素材です。両面を使えるため、ニーモニック単語をコンパクトに保存できます。

現在のリファレンス実装では大径のM8ワッシャーを使用し、12単語ニーモニックを7枚で組む例を示していますが、M8、12単語、7枚構成のいずれも方式そのものの必須条件ではありません。

## なぜ12単語に7枚使うのか

12単語には12の打刻面が必要なので、すべてのワッシャーの両面を使えば6枚にも記録できます。

現在のリファレンス構成では、あえて7枚を使用します。

- 1枚目：片面に1単語
- 2〜6枚目：両面に2単語ずつ
- 7枚目：片面に1単語

1枚目と7枚目の使わない面を、ボルトに通したときの外側へ向けます。これにより、組み上げた状態では点字状の打刻が外側から直接見えません。

これは物理的な見た目と保管方法の選択であり、符号化方式そのものの一部ではありません。制作者は6枚でも7枚でも、保管方法に合わせた別の構成でも構いません。また、外側の無刻印面は暗号化ではなく、バックアップを手に取ったり分解したりできる相手への実質的な保護として扱うべきではありません。

## なぜ11bitの2進数ではなく10進番号なのか

BIP39 Englishの各単語は、内部的には11bit indexで表現できます。初期案では、その11bitを内側 / 外側の打刻位置として直接記録していました。

現在の設計では、代わりに4桁の10進BIP39番号を記録します。これにより、通常のバックアップや復元時に、人間が英単語、11bit値、打刻位置の間を変換する必要をなくします。

その代わり、10進表現は本プロジェクト独自の規則となり、番号付き単語表が必要になります。

## なぜ1始まりなのか

現在のプロジェクト規則では、BIP39 English wordlistの1番目から2048番目を `0001`〜`2048` として扱います。

これは、印刷された人間向けの一覧で読みやすくすることを意図しています。BIP39ソフトウェア内部で使われる0始まりの11bit indexとは意図的に区別しています。

## なぜ点字数字なのか

標準点字数字は、6点式点字セルの上4点を使って10進数字を表現します。この既存の形を再利用することで、コンパクトで既知の視覚規則を持つ10進表現を使えます。

本プロジェクトでは図示を分かりやすくするため、4つの物理候補点を `1 3 / 2 4` と独自に番号付けしていますが、数字そのものの形は変更していません。

また、すべての該当領域が数字専用であるため、数符は省略します。

## なぜ点字セルをコンパクトな正方形状にするのか

旧2進方式では、円周上の各放射列を同じ単位として扱っていました。現在の設計では、意味のある視覚単位は4候補点からなる1つの10進数字です。

そのため、同じ数字に属する候補点を近接した正方形状のセルとしてまとめ、1桁を1つの記号として認識しやすくします。一方で、隣接する数字セルとは視覚的な間隔を確保します。

## なぜ8ブロックなのか

現在のリファレンス面には、

- 開始兼SET 1ブロック
- 語順 2桁
- BIP39番号 4桁
- CHECK 1桁

があります。

合計8つの論理ブロックです。

STARTとSETを統合することで、START専用ブロックを別に用意する必要がなくなり、数字セル同士の視覚的な間隔をより広く取れます。

## なぜSTARTとSETを統合するのか

開始位置とセットIDはいずれもニーモニック単語そのものではなく、メタデータです。両者を特徴的な1つのマーカーにまとめることで、2つの別領域を消費せずに両方の役割を持たせられます。

上下2つの固定点が開始構造を示し、左右のSET候補点でセットを表します。

現在の標準：

- A = 右候補点
- B = 左候補点
- 左右両方 / どちらもなし = 標準では予約または無効

SETは意図的に補助的なメタデータとして扱っています。ボルトによる物理的なグループ化、両面記録、別拠点保管などが、セット識別の追加文脈になります。

## なぜSETをCHECKで保護しないのか

CHECKは、各面の中で最も冗長性が低い情報であるBIP39番号を主に保護する目的で設けています。

SETには、ボルトでのグループ化や別セットを別場所に保管するといった物理的・文脈的な冗長性があります。語順も、ボルト上の並びや1枚の表裏の関係から物理的な冗長性を持たせられます。

CHECK対象をBIP39番号だけに限定することで、目的と手計算の方法も単純に保てます。

## なぜ単純mod 10なのか

Damm、Luhn、重み付きmod、2進 / CRC系チェックなど、複数の方式を検討しました。

単純mod 10を採用した理由は、

- 基本的な足し算だけで計算・確認できる
- 参照表やソフトウェアが不要
- 10進1桁だけが別の数字へ変わる単一数字誤りを検出できる
- 有効な点字数字パターン、`0001`〜`2048` の値域、BIP39チェックサム、独立したバックアップセットなど、他の検証層も存在する

ためです。

数学的に最も強い方式ではありません。複数の誤りが相殺される場合があります。この選択は、長期的に人間が理解しやすく、依存を少なくすることを優先したトレードオフです。

## なぜ紙の上から直接ポンチするのか

以前の工程では、候補位置を一度金属へ転写してから打刻していました。実際の試作では、実寸紙治具の上から直接打刻する方が簡単でした。

そのため、現在のリファレンス工程では、印刷した紙治具そのものを位置決めガイドとして使用します。

## なぜ特定の工具ではなくセンターポンチなのか

自動センターポンチは便利で、多くの利用者にとって想定しやすい工具ですが、この符号化方式は自動機構には依存しません。適切な手動センターポンチでも打刻できます。

そのため、プロジェクトでは `automatic-center-punch` ではなく `center-punch` という表現を使います。

## 応用性

現在の寸法、ブロック配置、12単語の例、7枚構成は1つのリファレンス実装です。方式の基本概念は、別のワッシャー寸法、語数、物理配置、積み方、打刻工具へ応用できます。ただし、その場合は必要に応じて新しい幾何配置と復元規則を作り、独立に検証する必要があります。

## 設計原則

本プロジェクトでは、次を優先します。

1. 印刷資料を使って人間が復元できること
2. 単純で監査可能な規則
3. 物理的な読みやすさ
4. 安価で一般的な材料
5. 想定する物理損傷に適した誤り検出
6. 復元時のソフトウェア依存を最小化すること
