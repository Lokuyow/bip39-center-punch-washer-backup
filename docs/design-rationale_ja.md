# 設計理由

[English](design-rationale.md)

この文書は、現在のリファレンス形式がなぜこの設計になっているのかを説明します。本プロジェクトは実験段階のため、これらの判断は実物試験やレビュー後に変更される可能性があります。

## なぜワッシャーなのか

ステンレスワッシャーは安価で入手しやすく、紙と比べて耐熱性があり、ボルトに通してまとめやすい素材です。両面を使えるため、ニーモニック単語をコンパクトに保存できます。

現在のリファレンス実装では大径のM8ワッシャーを使用し、12単語ニーモニックを7枚で組む例を示していますが、M8、12単語、7枚構成のいずれも方式そのものの必須条件ではありません。

## なぜ24mmのM8大径ワッシャーなのか

現在のリファレンス実装では、DIN 9021相当の外径24.0 mm、内径8.4 mmのM8平ワッシャーを採用しています。

この寸法は、現在の8ブロック構成と4点式の候補点を配置できる比較的広い環状面を確保しつつ、安価な一般部材として入手しやすいことを重視したリファレンス選択です。

この寸法自体は符号化方式の要件ではありません。別寸法へ変更する場合は、候補点の間隔、紙治具、打刻のしやすさ、復元時の判読性をあらためて検証する必要があります。

## なぜ12単語に7枚使うのか

12単語には12の打刻面が必要なので、すべてのワッシャーの両面を使えば6枚にも記録できます。

現在のリファレンス構成では、あえて7枚を使用します。

- 1枚目：片面に1単語
- 2〜6枚目：両面に2単語ずつ
- 7枚目：片面に1単語

1枚目と7枚目の使わない面を、ボルトに通したときの外側へ向けます。これにより、組み上げた状態では点字状の打刻が外側から直接見えません。

これは物理的な見た目と保管方法の選択であり、符号化方式そのものの一部ではありません。製作者は6枚でも7枚でも、保管方法に合わせた別の構成でも構いません。また、外側の無刻印面は暗号化ではなく、バックアップを手に取ったり分解したりできる相手への実質的な保護として扱うべきではありません。

## なぜ11bitの2進数ではなく10進番号なのか

BIP39 Englishの各単語は、内部的には11bit indexで表現できます。初期案では、その11bitを内側 / 外側の打刻位置として直接記録していました。

現在の設計では、代わりに4桁の10進BIP39番号を記録します。これにより、通常のバックアップや復元時に、人間が英単語、11bit値、打刻位置の間を変換する必要をなくします。

その代わり、本プロジェクト独自の **1始まり4桁10進番号 `0001`〜`2048`** という規則を使うため、番号付き単語表が必要になります。

## なぜ英単語の先頭4文字ではなく番号なのか

BIP39 English wordlistは、各単語を先頭4文字で一意に識別できるよう設計されています。そのため、メタルバックアップでは先頭4文字を直接記録する方法も合理的です。

Washer Punch39では、文字ではなく10進番号を採用しています。主な理由は、

- 打刻時に扱う記号を0〜9の10種類へ限定できる
- 同じ4点式セルだけで語順、BIP39番号、CHECKを表現できる
- アルファベット用の文字ポンチや文字ごとの異なる形状を必要としない
- 紙治具とセンターポンチだけで一定の幾何配置として記録できる

ためです。

一方で、番号から単語へ戻すには番号付きBIP39 English単語表が必要です。先頭4文字方式より自己記述性が低い点は、この設計の明確なトレードオフです。

## なぜ1始まりなのか

現在のプロジェクト規則では、BIP39 English wordlistの1番目から2048番目を `0001`〜`2048` として扱います。

これは、印刷された人間向けの一覧で読みやすくすることを意図しています。BIP39ソフトウェア内部で使われる0始まりの11bit indexとは意図的に区別しています。

## なぜ点字数字なのか

標準点字数字は、6点式点字セルの上4点を使って10進数字を表現します。この既存の形を再利用することで、コンパクトで既知の視覚規則を持つ10進表現を使えます。

また、すべての該当領域が数字専用であるため、数符は省略します。

## なぜSTARTとSETを統合するのか

開始位置とセットIDはいずれもニーモニック単語そのものではなく、メタデータです。両者を特徴的な1つのマーカーにまとめることで、2つの別領域を消費せずに両方の役割を持たせられます。

上下2つの固定点が開始構造を示し、左右のSET候補点でセットを表します。

現在の標準：

- A = 右候補点
- B = 左候補点
- 左右両方 / どちらもなし = 標準では予約または無効

SETは意図的に補助的なメタデータとして扱っています。ボルトによる物理的なグループ化や、セットA / Bを別拠点へ保管するといった運用も、セット識別の追加文脈になります。

## なぜSETと語順をCHECKで保護しないのか

CHECKは、各面で復元したい核心データであるBIP39番号を、単純な手計算でその場で検査する目的で設けています。

SETと語順には、各面のCHECKとは別の整合性確認があります。たとえば、

- 同一セット内ではSETが原則としてすべてAまたはすべてBになる
- 完全な12単語セットでは語順 `01`〜`12` が重複なく揃う
- ボルトに組んだ状態では物理的な並びも追加の手掛かりになる

といった確認ができます。

ただし、これらは完全な誤り検出ではありません。たとえば2枚の語順を入れ替えた誤りは、`01`〜`12` がすべて揃っていても検出できません。SETや語順をCHECK対象外にしていることは、単純さと検出能力のトレードオフです。

CHECK対象をBIP39番号だけに限定することで、計算方法と目的を単純に保っています。

## なぜ単純mod 10なのか

Damm、Luhn、重み付きmod、2進 / CRC系チェックなど、複数の方式を検討しました。

単純mod 10を採用した理由は、

- 基本的な足し算だけで計算・確認できる
- 参照表やソフトウェアが不要
- BIP39番号4桁またはCHECKのうち、1桁だけが別の数字へ変わる単一数字誤りを検出できる
- 有効な点字数字パターン、`0001`〜`2048` の値域、BIP39チェックサム、独立したバックアップセットなど、他の確認手段も併用できる

ためです。

一方、単純mod 10は桁の位置に重みを付けないため、**桁の入れ替えを検出できません**。たとえば `1391` と `1931` はどちらも各桁の合計が14なので、同じCHECKになります。複数の数字の変化が相殺される場合もあります。

また、BIP39チェックサムは追加の確認手段にはなりますが、元のニーモニックとの一致を保証するものではありません。現在の12単語リファレンスではBIP39チェックサムは4bitなので、誤った単語列でもチェックサム上は有効になる場合があります。

このため、CHECK、値域、BIP39チェックサムなどはいずれも**検証の層**として扱い、単独で完全性を保証するものとは考えません。可能であれば、ウォレットフィンガープリントや既知の受取アドレス、独立したバックアップなど別の情報でも最終確認します。

単純mod 10は数学的に最も強い方式ではありません。この選択は、長期的に人間が理解しやすく、復元時の依存を少なくすることを優先したトレードオフです。

## なぜ紙治具の上から直接打刻するのか

現在のリファレンス手順では、紙治具をワッシャーへ位置合わせして固定し、その紙の上からセンターポンチで直接打刻します。

紙治具の穴位置をいったんペンでワッシャーへ転記してから打刻する方法と比べ、直接打刻は、

- 作業工程を減らせる
- ペンで印を写す位置ずれや転記ミスを減らせる
- すべての候補点を印刷した同一治具を使える

という利点があります。

紙治具自体にはシード固有の選択情報を印刷しません。使用後の穴や打痕は作業履歴を示しますが、治具には全候補点があるため、複数回の使用によって穴が増えるほど個別の秘密情報との対応は薄くなります。

## 応用性

現在の寸法、ブロック配置、12単語の例、7枚構成は1つのリファレンス実装です。方式の基本概念は、別のワッシャー寸法、語数、物理配置、積み方、打刻工具へ応用できます。ただし、その場合は必要に応じて新しい幾何配置と復元規則を作り、独立に検証する必要があります。

## 設計原則

本プロジェクトでは、次を優先します。

1. 印刷資料を使って人間が復元できること
2. 単純で監査可能な規則
3. 物理的な読みやすさ
4. 安価で一般的な材料
5. 想定する物理損傷や読み取り誤りを検出しやすいこと
6. 復元時のソフトウェア依存を最小化すること
